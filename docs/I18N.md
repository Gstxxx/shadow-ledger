# Idiomas (i18n)

Sem dependências: `src/i18n` tem o runtime, os dicionários e os formatadores. **pt-BR é a fonte da verdade** (define as chaves); **en é obrigatório e completo** — o teste falha se faltar chave, sobrar chave ou divergirem os `{parâmetros}`. O inglês usa exatamente os termos de [GLOSSARY-EN.md](GLOSSARY-EN.md).

## Uso

```tsx
import { useT } from '../../i18n';

function Cabecalho({ dias, caixa }: { dias: number; caixa: number }) {
  const { t, fmt, lang, setLang } = useT(); // re-renderiza quando o idioma muda
  return <p>{t('game.topbar.status', { dias, caixa: fmt.money(caixa) })}</p>;
}
```

Fora de React (motor, utilitários): `import { t, fmt, getLang } from '../i18n'`. Lembre que `t()` fora de componente não re-renderiza nada; guarde no estado `{ key, params }` e traduza na hora de exibir.

- Chaves tipadas: `t('chave.inexistente')` não compila (`Key` vem do pt-BR).
- Interpolação: `{nome}`. Plural: `{n, plural, =0 {nenhum} one {# item} other {# itens}}` (`#` = número; regras do `Intl.PluralRules` do idioma).
- Dinheiro, datas e números **não entram na string**: passe `fmt.money(x)` (pt-BR `US$ 1,2 mi`, en `$1.2M`), `fmt.moneyFull`, `fmt.amount`, `fmt.pct`, `fmt.tons`, `fmt.num`, `fmt.date` como parâmetro.
- Idioma inicial: o salvo em `localStorage['sl.lang']`; senão o do navegador (`pt*` → pt-BR, resto → en). `setLang('en')` troca, persiste e atualiza `<html lang>`.
- Faltou a tradução em runtime? Cai para pt-BR e, por último, mostra a própria chave.

## Estrutura

```
src/i18n/
  core.ts  icu.ts  format.ts  types.ts  index.ts   runtime
  pt-BR/<área>.ts   en/<área>.ts                   dicionários planos 'ns.chave': 'texto'
  pt-BR/index.ts    en/index.ts                    juntam as áreas
  lookup.ts                                        nomes por id (itens, países, traços)
  __tests__/                                       paridade de chaves, plural/formatação, texto solto
```

Convenção de chaves: `área.componente.item` (`game.topbar.pause`, `menu.new.title`, `item.bodyguard.name`, `msg.sim.politicalShift`). Dados indexados por id usam o id na chave.

## Adicionar uma mensagem

1. Escreva a chave em `src/i18n/pt-BR/<área>.ts` e a tradução em `src/i18n/en/<área>.ts` (mesmos parâmetros).
2. Use `t('chave', params)` no componente.
3. `npx vitest run src/i18n`.

## Adicionar um idioma

1. Acrescente o código em `Lang`/`LANGS`/`LANG_LABEL` (`src/i18n/types.ts`).
2. Crie `src/i18n/<código>/` com um arquivo por área, copiando as chaves do pt-BR, e registre-o em `DICTS` (`core.ts`).
3. Estenda `UNITS` e o prefixo de moeda em `format.ts` se o idioma não usar `US$`/`$`.
4. Atualize os testes de paridade (`i18n.test.ts`) para incluir o novo idioma e o glossário dele (se houver).

## Texto solto no JSX (catraca)

`src/i18n/__tests__/loose-strings.test.ts` acha texto escrito direto em JSX (`>Comprar<`, `title="Fechar"`) fora do i18n. Cada arquivo tem um teto em `loose-baseline.json`: o teste falha se um arquivo **piorar** ou se um arquivo novo trouxer texto solto. Ao migrar um arquivo, baixe o teto com:

```bash
node src/i18n/baseline.mjs
```

A meta é a baseline vazia (`{}`).

## Estado salvo e mensagens do motor

Logs e avisos do motor devem ser guardados como `{ key, params }` (não como texto final) para trocar de idioma sem perder o histórico; ver as notas de integração em `side-session-notes/…/i18n-engine.md`.
